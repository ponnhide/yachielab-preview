# 検証環境の運用と構造

## コンテンツと公開出力

Sheets は編集するコンテンツと一部の表示設定の入力元、GAS は HTML の生成・共通部品の更新と GitHub への書き込み、GitHub Pages は生成済みファイルの配信を担当します。ブラウザが Sheets を直接読む構造ではありません。

共通部品は header / footer / sidebar / mobile menu、本文は独立したページ用タブから生成されます。ページ登録とパラメータ定義を確認してから新規ページを追加してください。非登録ページを一律に生成対象に足す必要はありません。

`Update all registered pages` は登録された20ページの `.posts` 本文をまとめて更新します。`Update shared components` は4つの共通部品を index を含む21ページへ1コミットで反映し、各ページの `.posts` 本文を維持します。`Update the current page` は登録ページなら本文、共通部品タブならその部品だけを対象にします。これらの更新範囲を混同しないでください。

独立ページの空の Lab セルは本文の終了を表します。一方、header などの共通部品には Lab が空の意図したラッパー行があり、空の Lab を終了条件として扱いません。Function とデータを持つラッパー行を、空欄の掃除と一緒に削除しないでください。

論文著者の強調に使う別名は、Function が `Member` の行だけから集めます。現在の表示方針を維持するため、`Alumni` 行を自動で加えません。別名を追加するときも行の種類を確認してください。

HTML、CSS、JS、画像、PDF の配信場所は従来の URL を維持しています。実ファイルの大移動には、Sheets の入力、GAS の生成結果、CSS、JS、外部からの直接リンクをまとめて更新する必要があります。構造整理では、まず編集元・出力・資料・検査を分けます。

CSS は安定した入口ファイルから基礎・レイアウト・共通部品・レスポンシブ処理を読み込み、ページ用・コンポーネント用・外部ライブラリ用・旧版を別のディレクトリで管理します。旧ファイル名は入口として維持します。詳しくは [CSS の構造](../css/README.md) を参照してください。JS は `common.js` の `YachieSite` に共通の状態と処理をまとめ、ホームページ・モバイルメニュー・ニュースの処理を各ファイルで扱います。

## ヘッダーロゴの管理

以前の2つの合成 SVG は、次の4つの個別ファイルへ分けています。元のパス形状、ロゴの大きさ、横の透明余白と左右位置を保持しています。previewでは2つのロゴの縦の隙間を従来の1.5倍にしています。上側は y=0 のまま、下側の開始位置を y=185 から y=213.41425 へ移し、全体のキャンバスを772×343.41425へ広げています。

| パス | 役割・viewBox |
| --- | --- |
| `img/header-ubc-white.svg` | 上側の白ロゴ、`0 0 772 129`。 |
| `img/header-ubc-teal.svg` | 上側の teal ロゴ、`0 0 772 129`。 |
| `img/header-osaka-white.svg` | 下側の白ロゴ、`0 185 772 130`。 |
| `img/header-osaka-teal.svg` | 下側の teal ロゴ、`0 185 772 130`。 |

白と teal はそれぞれ `.logo-stack` / `.logo-canvas` にまとめ、JS は白の親レイヤーを切り取ります。子 SVG を個別に拡大・移動して色境界を作りません。間隔は `css/components.css` の `.logo-stack` にある `--header-logo-extra-gap: 28.41425`（SVG座標単位）で一括管理します。元の実描画範囲の隙間56.8285へ、その半分28.41425を加えています。キャンバスの高さと下側の開始位置はこの値から同時に計算し、白と teal に同じ間隔を適用します。この値を0に戻すと元の間隔になります。内部キャンバスは幅に比例した自然高を保持するため、スクロールで白の親レイヤーを切り取っても子 SVG の大きさや配置は変わりません。

Sheet のヘッダーで使っている `two_logos_on_white_on_black.svg` と `two_logos_teal_on_white.svg` の指定は維持します。生成時に `Renderer.gs` が対象を個別 SVG と `button.logo-control[data-affiliation]` に変換します。描画は `frontlogo` / `backlogo` の安定した1組とし、描画用の行は `All / Common` で両方の所属ロゴを表示します。以前の `frontlogo2` / `backlogo2` は重複して描画しません。その他の画像は従来の1画像として扱い、元の合成 SVG の公開 URL も残しています。

ロゴをクリックすると、ページを再読み込みせずに所属を切り替えます。選択した所属は URL と内部リンクに反映します。URL に有効な `affil` の指定がない初期表示は、日本語では Osaka、英語・中国語では UBC です。明示的な選択がある場合はその所属を保ちます。`yuka` は引き続き GAS の更新対象外ですが、共通 JS が旧ヘッダーを実行時に補完して同じ選択操作に対応します。

## ロゴの透明度と切り替え時間

専用 Sheet の `header!F2`（ID が `head` の行の Style）で、次の3つの CSS custom properties を設定します。他のレイアウト設定も同じセルに残せます。

```css
--lab-logo-active-opacity: 1;
--lab-logo-inactive-opacity: 0.5;
--lab-logo-transition-duration: 300ms;
```

| 設定 | 初期値・許容値 |
| --- | --- |
| `--lab-logo-active-opacity` | 選択中のロゴ。初期値1、有限の数値0〜1。 |
| `--lab-logo-inactive-opacity` | 非選択のロゴ。初期値0.5、有限の数値0〜1。 |
| `--lab-logo-transition-duration` | 透明度の切り替え時間。初期値300ms、`ms` / `s` 単位で0〜10000ms。 |

値を変更した後は、header タブで `Update the current page`、または `Update shared components` を実行します。GAS はこの3項目だけを数値にした公開 `site-settings.json` を、HTML・資産と同じコミットへ保存します。各ページの JS がこの JSON を取得するため、GAS で本文やヘッダーを更新していない `yuka` にも設定が反映されます。公開 JSON に Sheet の本文や認証情報は含めません。不正値・範囲外・単位のない時間指定は、API 通信前に明示的なエラーとします。

## 所属ごとのコンテンツとモバイル操作

表示対象は Sheet の Lab セルを基準にします。`UBC` は UBC 選択時、`Osaka` は Osaka 選択時、`All` は両方で表示します。言語の条件は Language セルで別に指定します。URL や本文の単語から所属を推測して上書きしません。

Join us の UBC 向け本文は Lab=`UBC`、大阪向け本文は Lab=`Osaka`、共通タイトルは Lab=`All` です。冒頭の所属へのジャンプリンクとそのラッパー行は、Sheet に内容を残したまま Function=`Pass` として出力対象から外しています。所属の切り替えはロゴの操作へまとめています。

モバイル用の所属選択は、`mobilemenu` タブの `mobile-lab-switch` ラッパー内にある2つの Content 行で管理します。ID は `mobile-ubc-lab` / `mobile-osaka-lab`、Lab / Language は `All / Common` とし、両方の選択ボタンを常に表示します。生成処理がこれらの行を通常のリンクではなく所属選択のボタンに変換します。大学の外部リンクやホームへのリンクは別に維持します。

## 安全に GAS を更新する

`cms/` のソースが版管理上の編集元です。ブラウザの GAS エディタで変更した場合も、秘密情報を除いたソースを `cms/` に戻して差分を記録します。ライブラリの固定バージョン・`appsscript.json` の設定も確認します。生成された HTML だけを直して、生成処理を直し忘れないようにしてください。

| ファイル | 担当 |
| --- | --- |
| `Cms.gs` | メニュー、更新の実行、実行時のロック、全ページ・共通部品の更新。 |
| `SheetRepository.gs` | 対象 Sheet の読み取りと、1回の実行内で共有する状態。 |
| `Renderer.gs` | 行データから既存のコンポーネント HTML を生成。 |
| `SheetStyles.gs` | Sheet の属性・単位・見た目設定を明示的に HTML へ反映。 |
| `Publications.gs` | 論文データの取得・解析・引用表示。 |
| `AssetStore.gs` | 画像・PDF の取得と検証、更新する資産の収集。 |
| `GitHub.gs` | 生成した HTML・資産・数値の `site-settings.json` をまとめてコミット。 |
| `PreviewIsolation.gs` | 検証用の Sheet・リポジトリ・ブランチ・書き込み先の検査と、プレビュー HTML の正規化。 |
| `showdown.gs` | 同梱した Markdown ライブラリ Showdown 2.0.0。 |
| `appsscript.json` | 実行環境、依存ライブラリ、OAuth 権限。 |

元の `Update_github.gs` / `archive.gs` / `get_publications.gs` / `test.gs` は移行用の空ファイルとして維持しています。以前の実装は `cms/legacy/` に保存し、通常の実行には読み込みません。専用 GAS に反映するときに `legacy/` の旧実装を一緒に追加すると、関数が重複するため除外してください。

外部 GAS ライブラリは **Cheerio 14** に固定しています。使われていない Parser と cUseful は依存から除外しました。V8、タイムゾーン Asia/Tokyo は維持しています。OAuth 権限は以下を [appsscript.json](../cms/appsscript.json) に明示しています。

| OAuth scope | 用途 |
| --- | --- |
| `spreadsheets.currentonly` | この GAS が紐づく現在の Sheet の読み取りと更新。 |
| `drive.readonly` | Sheet が参照する Drive ファイルの読み取り。 |
| `script.external_request` | GitHub API、論文データ、外部資産の取得。 |
| `script.container.ui` | Sheet のカスタムメニューと実行結果の表示。 |

反映先はコピーした専用 GAS です。元の GAS を同時に開いて編集しません。トークンは専用 GAS の Script Properties に置き、ソースコードではプロパティから読みます。更新先を変更するにはコードと隔離ガードの設定を同時に変える必要があり、通常の検証更新では変更しません。

初回実行時の Google 権限承認、期限切れトークンの再発行、GitHub の権限変更は、ファイルの編集とは別の運用作業です。GitHub API が失敗した場合は、公開が完了したとみなさず、HTTP エラーと実際のブランチ・公開結果を確認します。

## CSS と Sheets の見た目設定

基本レイアウトは CSS、対応している項目の個別調整は Sheets で管理します。対応するパラメータ名・対象要素・単位を確認してから値を設定します。特定の設定を反映させるために `!important` を追加し続ける運用は避けます。

Sheets の例としては画像の幅・高さ、余白、配置、文字サイズなどがあります。定義があるだけで生成関数が読み取っていなければ反映されないため、変更時には生成結果とブラウザの計算後スタイルの両方を確認します。CSS の整理後も、対応する Sheet 設定を実際に変えるテストを行ってください。

論文行の `/* img width` は、論文行全体を基準に画像欄の幅へ反映します。`Publication (custom)` は P 列、`Publication` は K 列です。現在の `publications!P8:P9` は `clamp(60px, 50%, 350px)` です。行の50%（最小60px・最大350px）を確保し、本文は残りの幅へ折り返します。画像自身は欄の幅を使い、`/* img height` が空なら縦横比を保持します。高さ指定は画像自身へ反映します。幅指定のない行は従来の画像欄（PC約20%・モバイル約25%）を維持します。Sheet の値を保存した後、`Update the current page` を実行して公開HTMLを再生成してください。

## 動作の確認

表示が変わらないことの確認には、静的検査だけでなくブラウザが必要です。変更した領域に応じて以下を確認します。

- ホームページと代表的な本文ページで、PC とモバイルの表示。
- EN / JA / ZH と UBC / Osaka の選択、URL の維持、1回のクリックで反映されること。
- ロゴの白と色付きの境界、スクロール、画面のリサイズ、フッター付近。
- メニューの開閉、素早く連続操作した場合、ページ遷移後の状態。
- ニュースや埋め込みの表示、外部ウィジェットの再描画。
- 画像・PDF・内部リンク、コンソールの新しいエラー。
- GAS の更新後も CSS / JS の変更とプレビュー隔離が残ること。

元の HTML の文書モードを変えると、単位のない既存値や幅・高さの計算が変わる可能性があります。`DOCTYPE` をまとめて追加する変更は、レイアウト調整とブラウザ比較を伴う別の作業として扱います。

## 資産の取り扱い

`docs/assets/manifest.json` は、画像・PDF のパス、サイズ、SHA-256、ファイル実体、参照証拠、同一内容のグループを記録します。「参照候補なし」は削除の許可ではありません。CSS/JS で組み立てるファイル名、GAS が挿入する HTML、Sheet のセル、過去のニュース、外部からの直接 URL を確認してください。

同じ画像が複数のファイル名で存在しても、URL は別です。バイトが同一であるだけでは安全に削除できません。作業元の `.afdesign` や `.HEIC`、古い CSS も、用途が確認できるまで保留します。

整理する際は、変更前の一覧を保存し、対象と参照を書き出してから、生成元と参照を更新して検証します。新しい画像はブラウザ向けの実際の画像形式と分かりやすい名前で追加します。Drive の共有ページやログイン HTML を画像として保存しないでください。監査はそのような形式の不一致も検出します。

通常のページ更新では、すでに公開先にあるファイル名の資産を再利用します。同名の Drive ファイルや外部画像の内容を変えた場合は、`Refresh linked assets on current page` を使って取り直します。既存の公開ファイル名・URL を保ったまま、選択ページが参照する資産と本文をまとめて保存します。リポジトリ内の相対パスを直接指定した資産は外部から取得し直しません。

取得時は画像・PDF の実体と拡張子が一致すること、HTML や空のファイルでないこと、1ファイルが16 MiB以下であることを確認します。同じ更新内で、同じファイル名に異なる内容を保存しようとした場合は中止します。16 MiBを超える資産は GitHub から追加し、Sheet ではその公開パスを参照してください。

## 本番へ移すとき

この検証環境のリポジトリ名、ブランチ名、URL、`noindex`、Analytics、認証情報、隔離ガードは検証用です。検証結果をそのまま本番へコピーする操作は別の変更として扱い、差分と公開設定を確認します。検証作業中に本番側の機密情報・認証・Pages 設定を変更しません。
