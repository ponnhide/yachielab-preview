# 検証環境の運用と構造

## コンテンツと公開出力

Sheets は編集するコンテンツと一部の表示設定の入力元、GAS は HTML の生成・共通部品の更新と GitHub への書き込み、GitHub Pages は生成済みファイルの配信を担当します。ブラウザが Sheets を直接読む構造ではありません。

共通部品は header / footer / sidebar / mobile menu、本文は独立したページ用タブから生成されます。ページ登録とパラメータ定義を確認してから新規ページを追加してください。非登録ページを一律に生成対象に足す必要はありません。

`Update all registered pages` は登録された20ページの `.posts` 本文を対象にします。`Update shared components` は4つの共通部品を index を含む21ページへまとめて反映し、各ページの `.posts` 本文を維持します。`Update the current page` は登録ページなら本文、共通部品タブならその部品だけを対象にします。通常は差分を再生成し、変更がない行やページを再利用します。変更がある HTML・資産・公開設定は1コミットにまとめます。これらの更新範囲を混同しないでください。

独立ページの空の Lab セルは本文の終了を表します。一方、header などの共通部品には Lab が空の意図したラッパー行があり、空の Lab を終了条件として扱いません。Function とデータを持つラッパー行を、空欄の掃除と一緒に削除しないでください。

論文著者の強調に使う別名は、Function が `Member` の行だけから集めます。現在の表示方針を維持するため、`Alumni` 行を自動で加えません。別名を追加するときも行の種類を確認してください。

HTML、CSS、JS、画像、PDF の配信場所は従来の URL を維持しています。実ファイルの大移動には、Sheets の入力、GAS の生成結果、CSS、JS、外部からの直接リンクをまとめて更新する必要があります。構造整理では、まず編集元・出力・資料・検査を分けます。

CSS は安定した入口ファイルから基礎・レイアウト・共通部品・レスポンシブ処理を読み込み、ページ用・コンポーネント用・外部ライブラリ用・旧版を別のディレクトリで管理します。旧ファイル名は入口として維持します。詳しくは [CSS の構造](../css/README.md) を参照してください。JS は `common.js` の `YachieSite` に共通の状態と処理をまとめ、ホームページ・モバイルメニュー・ニュースの処理を各ファイルで扱います。

## 差分更新と再取得

通常の更新は、入力値・文字の装飾・パラメータ定義・生成処理のバージョンを確認し、同じ内容を生成できる行の HTML を再利用します。論文ではメンバー別名や雑誌名の置換、Member / Alumni では前後の行によるグループの開始・終了も再利用条件に含めます。参照するローカル画像・PDF の SHA が変わった場合も再生成します。新しく保存する資産は、その内容から計算した SHA と公開時の SHA を確認します。

| メニュー・関数 | 用途 |
| --- | --- |
| `Update the current page` / `update_webpage` | 通常の差分更新。条件が同じ行の HTML を再利用します。 |
| `Update all registered pages` / `update_all_webpages` | 登録ページをまとめて差分更新します。 |
| `Update shared components` / `update_shared_components` | 共通部品を差分更新し、対象ページへまとめて反映します。 |
| `Rebuild current page (ignore HTML cache)` / `rebuild_current_page` | HTML 行のキャッシュを使わず再生成します。有効な PubMed のデータキャッシュは利用します。画像の強制再取得とは別の操作です。 |
| `Refresh external data on current page` / `refresh_current_data` | 外部データを使う `Publication` 行を再生成し、PubMed のデータキャッシュも読まずに取得し直します。手入力の custom 論文は入力値に従います。 |
| `Refresh linked assets on current page` / `refresh_current_assets` | HTML 行を再生成して画像を再取得し、Drive / Dropbox PDF も上限内で同期を試みます。通常更新では PDF リンクを維持します。外部論文データの強制再取得とは別の操作です。 |

`Publication` 行と Drive URL を含む行の HTML キャッシュは生成から6時間です。再利用しても生成時刻を延長しません。PubMed の取得結果も最大6時間保存しますが、期待する PMID と空でない題名を検証した結果だけを使います。破損したキャッシュや異なる PMID は取得元へ戻って読み直し、強制再取得が失敗した場合は旧データを成功した結果として返しません。bioRxiv は HTML 行を再生成する必要があるときに取得します。

検証済みの新しい MEDLINE を取得した場合は、旧キーを削除してから保存します。保存に失敗した場合は削除を再度試み、サイズのため保存を省略する場合も先に旧キーを削除します。後の HTML 再生成で古い引用へ戻ることを防ぐため、強制再取得で旧キーを消せない場合は明示的なエラーとします。通常の更新では、キャッシュ機能が利用できなくても有効な取得結果を表示できます。

## 自動管理タブ `_cms_cache`

`_cms_cache` は表示されたままの自動管理タブです。編集元は各コンテンツタブ・共通部品タブ・parameters であり、キャッシュを本文の編集元にしません。次の11列は GAS がまとめて読み書きするため、通常の作業では編集しません。

| 列 | 内容 |
| --- | --- |
| `Type` | 行 (`row`) / ページ (`page`) の記録の種類。 |
| `Key` | 再利用する記録の内部キー。 |
| `Source` | 入力タブまたはページの名前。 |
| `SourceId` | 入力タブの識別子、またはページ内の更新対象。 |
| `Row` | 入力元の行番号。ページの記録では使いません。 |
| `Fingerprint` | 入力・生成条件、または生成した部品のハッシュ。 |
| `RendererVersion` | 生成処理のキャッシュ用バージョン。 |
| `GeneratedAt` | 実際に生成した時刻。再利用では延長しません。 |
| `HTML` | 生成した行の HTML。ページの記録では空です。 |
| `Dependencies` | 参照するローカル資産のパスと SHA。 |
| `SHA` | 行の HTML の SHA、または公開成功を確認したページの SHA。 |

保存する記録は最大3000件で、上限を超えた場合は古い記録から外します。40000文字を超える HTML などはキャッシュに保存せず、必要なときに元の入力から生成します。キャッシュが欠落・破損していても、入力タブから再生成します。

キャッシュ用の生成バージョンは `cms/RenderCache.gs` の `CMS_CACHE_RENDERER_VERSION_` で手動管理します。Renderer / SheetStyles / Publications / Showdown、HTML 正規化、依存ライブラリなど、生成結果に影響する実装を変えたらこの値も更新してください。入力値・装飾・パラメータ定義の変更は再利用条件から自動で検出します。

キャッシュの記録は GitHub への公開成功後に行います。ページの再利用は前回成功時の公開 SHA との一致を確認し、公開状態が変わった場合やキャッシュが壊れた場合は再利用を止めます。公開は成功してキャッシュ保存だけが失敗した場合も、次回の SHA 確認で古い行の HTML を戻さずに再生成・必要な外部データの再取得へ進めるようにします。取得や公開自体の失敗は成功した記録として保存しません。この回復処理のネイティブでの実測は、[検証記録](verification.md) で別途扱います。

変更確認に使うハッシュは `Hashes.gs` が V8 内で計算し、行ごとの Apps Script サービス呼び出しを避けます。入力の値と、Renderer が実際に使うリッチテキストだけを比較します。空欄や `/*` で始まる仮入力の書式は、Renderer と同様に読取りを省略します。新しく作成するキャッシュタブは末尾に置き、元の選択タブを維持します。

## ヘッダーロゴの管理

以前の2つの合成 SVG は、次の4つの個別ファイルへ分けています。元のパス形状、ロゴの大きさ、横の透明余白と左右位置を保持しています。previewでは2つのロゴの縦の隙間を従来の1.5倍にしています。上側は y=0 のまま、下側の開始位置を y=185 から y=213.41425 へ移し、全体のキャンバスを772×343.41425へ広げています。

| パス | 役割・viewBox |
| --- | --- |
| `img/header-ubc-white.svg` | 上側の白ロゴ、`0 0 772 129`。 |
| `img/header-ubc-teal.svg` | 上側の teal ロゴ、`0 0 772 129`。 |
| `img/header-osaka-white.svg` | 下側の白ロゴ、`0 185 772 130`。 |
| `img/header-osaka-teal.svg` | 下側の teal ロゴ、`0 185 772 130`。 |

白と teal はそれぞれ `.logo-stack` / `.logo-canvas` にまとめ、JS は白の親レイヤーを切り取ります。子 SVG を個別に拡大・移動して色境界を作りません。間隔は `css/components.css` の `.logo-stack` にある `--header-logo-extra-gap: 28.41425`（SVG座標単位）で一括管理します。元の実描画範囲の隙間56.8285へ、その半分28.41425を加えています。キャンバスの高さと下側の開始位置はこの値から同時に計算し、白と teal に同じ間隔を適用します。この値を0に戻すと元の間隔になります。内部キャンバスは幅に比例した自然高を保持するため、スクロールで白の親レイヤーを切り取っても子 SVG の大きさや配置は変わりません。

Sheet のヘッダーで使っている `two_logos_on_white_on_black.svg` と `two_logos_teal_on_white.svg` の指定は維持します。生成時に `Renderer.gs` が対象を個別 SVG と `button.logo-control[data-affiliation]` に変換します。描画は `frontlogo` / `backlogo` の安定した1組とし、描画用の行は `All / Common` で両方の所属ロゴを表示します。以前の `frontlogo2` / `backlogo2` は重複して描画しません。その他の画像は従来の1画像として扱い、元の合成 SVG の公開 URL も残しています。

ロゴをクリックすると、ページを再読み込みせずに所属を切り替えます。選択した所属は URL と内部リンクに反映します。URL に有効な `affil` の指定がない初期表示は、日本語では Osaka、英語・中国語では UBC です。明示的な選択がある場合はその所属を保ちます。`yuka` は引き続き GAS の更新対象外ですが、共通 JS が旧ヘッダーを実行時に補完して同じ選択操作に対応します。

## ロゴの透明度と切り替え時間

専用 Sheet の `header!F2`（ID が `head` の行の Style）で、次の3つの CSS custom properties を設定します。他のレイアウト設定も同じセルに残せます。

```css
--lab-logo-active-opacity: 1;
--lab-logo-inactive-opacity: 0.5;
--lab-logo-transition-duration: 300ms;
```

| 設定 | 初期値・許容値 |
| --- | --- |
| `--lab-logo-active-opacity` | 選択中のロゴ。初期値1、有限の数値0〜1。 |
| `--lab-logo-inactive-opacity` | 非選択のロゴ。初期値0.5、有限の数値0〜1。 |
| `--lab-logo-transition-duration` | 透明度の切り替え時間。初期値300ms、`ms` / `s` 単位で0〜10000ms。 |

値を変更した後は、header タブで `Update the current page`、または `Update shared components` を実行します。GAS はこの3項目だけを数値にした公開 `site-settings.json` を、HTML・資産と同じコミットへ保存します。各ページの JS がこの JSON を取得するため、GAS で本文やヘッダーを更新していない `yuka` にも設定が反映されます。公開 JSON に Sheet の本文や認証情報は含めません。不正値・範囲外・単位のない時間指定は、API 通信前に明示的なエラーとします。

## 所属ごとのコンテンツとモバイル操作

表示対象は Sheet の Lab セルを基準にします。`UBC` は UBC 選択時、`Osaka` は Osaka 選択時、`All` は両方で表示します。言語の条件は Language セルで別に指定します。URL や本文の単語から所属を推測して上書きしません。

Join us の UBC 向け本文は Lab=`UBC`、大阪向け本文は Lab=`Osaka`、共通タイトルは Lab=`All` です。冒頭の所属へのジャンプリンクとそのラッパー行は、Sheet に内容を残したまま Function=`Pass` として出力対象から外しています。所属の切り替えはロゴの操作へまとめています。

モバイル用の所属選択は、`mobilemenu` タブの `mobile-lab-switch` ラッパー内にある2つの Content 行で管理します。ID は `mobile-ubc-lab` / `mobile-osaka-lab`、Lab / Language は `All / Common` とし、両方の選択ボタンを常に表示します。生成処理がこれらの行を通常のリンクではなく所属選択のボタンに変換します。大学の外部リンクやホームへのリンクは別に維持します。

## 安全に GAS を更新する

`cms/` のソースが版管理上の編集元です。ブラウザの GAS エディタで変更した場合も、秘密情報を除いたソースを `cms/` に戻して差分を記録します。ライブラリの固定バージョン・`appsscript.json` の設定も確認します。生成された HTML だけを直して、生成処理を直し忘れないようにしてください。

| ファイル | 担当 |
| --- | --- |
| `Cms.gs` | メニュー、更新の実行、実行時のロック、全ページ・共通部品の更新。 |
| `SheetRepository.gs` | 対象 Sheet の読み取りと、1回の実行内で共有する状態。 |
| `Renderer.gs` | 行データから既存のコンポーネント HTML を生成。 |
| `SheetStyles.gs` | Sheet の属性・単位・見た目設定を明示的に HTML へ反映。 |
| `Publications.gs` | 論文データの取得・解析・引用表示。 |
| `AssetStore.gs` | 画像・PDF の取得と検証、更新する資産の収集。 |
| `RenderCache.gs` | 入力・資産の変更判定、行とページの再利用、自動管理タブの記録。 |
| `GitHub.gs` | 生成した HTML・資産・数値の `site-settings.json` をまとめてコミット。 |
| `PreviewIsolation.gs` | 検証用の Sheet・リポジトリ・ブランチ・書き込み先の検査と、プレビュー HTML の正規化。 |
| `showdown.gs` | 同梱した Markdown ライブラリ Showdown 2.0.0。 |
| `appsscript.json` | 実行環境、依存ライブラリ、OAuth 権限。 |

元の `Update_github.gs` / `archive.gs` / `get_publications.gs` / `test.gs` は移行用の空ファイルとして維持しています。以前の実装は `cms/legacy/` に保存し、通常の実行には読み込みません。専用 GAS に反映するときに `legacy/` の旧実装を一緒に追加すると、関数が重複するため除外してください。

外部 GAS ライブラリは **Cheerio 14** に固定しています。使われていない Parser と cUseful は依存から除外しました。V8、タイムゾーン Asia/Tokyo は維持しています。OAuth 権限は以下を [appsscript.json](../cms/appsscript.json) に明示しています。

| OAuth scope | 用途 |
| --- | --- |
| `spreadsheets.currentonly` | この GAS が紐づく現在の Sheet の読み取りと更新。 |
| `drive.readonly` | Sheet が参照する Drive ファイルの読み取り。 |
| `script.external_request` | GitHub API、論文データ、外部資産の取得。 |
| `script.container.ui` | Sheet のカスタムメニューと実行結果の表示。 |

反映先はコピーした専用 GAS です。元の GAS を同時に開いて編集しません。トークンは専用 GAS の Script Properties に置き、ソースコードではプロパティから読みます。更新先を変更するにはコードと隔離ガードの設定を同時に変える必要があり、通常の検証更新では変更しません。

初回実行時の Google 権限承認、期限切れトークンの再発行、GitHub の権限変更は、ファイルの編集とは別の運用作業です。GitHub API が失敗した場合は、公開が完了したとみなさず、HTTP エラーと実際のブランチ・公開結果を確認します。

## CSS と Sheets の見た目設定

基本レイアウトは CSS、対応している項目の個別調整は Sheets で管理します。対応するパラメータ名・対象要素・単位を確認してから値を設定します。特定の設定を反映させるために `!important` を追加し続ける運用は避けます。

Sheets の例としては画像の幅・高さ、余白、配置、文字サイズなどがあります。定義があるだけで生成関数が読み取っていなければ反映されないため、変更時には生成結果とブラウザの計算後スタイルの両方を確認します。CSS の整理後も、対応する Sheet 設定を実際に変えるテストを行ってください。

論文行の `/* img width` は、論文行全体を基準に画像欄の幅へ反映します。`Publication (custom)` は P 列、`Publication` は K 列です。現在の `publications!P8:P9` は `clamp(60px, 50%, 350px)` です。行の50%（最小60px・最大350px）を確保し、本文は残りの幅へ折り返します。画像自身は欄の幅を使い、`/* img height` が空なら縦横比を保持します。高さ指定は画像自身へ反映します。幅指定のない行は従来の画像欄（PC約20%・モバイル約25%）を維持します。Sheet の値を保存した後、`Update the current page` を実行して公開HTMLを再生成してください。

## 動作の確認

表示が変わらないことの確認には、静的検査だけでなくブラウザが必要です。変更した領域に応じて以下を確認します。

- ホームページと代表的な本文ページで、PC とモバイルの表示。
- EN / JA / ZH と UBC / Osaka の選択、URL の維持、1回のクリックで反映されること。
- ロゴの白と色付きの境界、スクロール、画面のリサイズ、フッター付近。
- メニューの開閉、素早く連続操作した場合、ページ遷移後の状態。
- ニュースや埋め込みの表示、外部ウィジェットの再描画。
- 画像・PDF・内部リンク、コンソールの新しいエラー。
- GAS の更新後も CSS / JS の変更とプレビュー隔離が残ること。

元の HTML の文書モードを変えると、単位のない既存値や幅・高さの計算が変わる可能性があります。`DOCTYPE` をまとめて追加する変更は、レイアウト調整とブラウザ比較を伴う別の作業として扱います。

## 資産の取り扱い

`docs/assets/manifest.json` は、画像・PDF のパス、サイズ、SHA-256、ファイル実体、参照証拠、同一内容のグループを記録します。全件の読みやすい一覧は [資産の参照一覧](assets/catalogue.md) です。公開 HTML とそこから読み込むローカル CSS / JS の参照、Sheet やソースだけに残る参照、参照未確認に分けます。「参照未確認」は削除の許可ではありません。CSS/JS で組み立てるファイル名、GAS が挿入する HTML、Sheet のセル、過去のニュース、外部からの直接 URL を確認してください。

一覧の「公開ページから辿れる参照」は静的な参照の分類であり、実際の表示や利用回数を測定したものではありません。入力・ソースだけの参照には旧 GAS やコメントも含みます。Sheet は指定した書き出し時点の内容だけを調べるため、再生成時は最新の JSON をリポジトリ外に用意してください。ハッシュ付きファイル名と更新用の `?v=` は、クエリを除いた実ファイルへ解決して検査します。ディレクトリ内の全ファイル数と、画像拡張子のファイル数も分けて記録します。

同じ画像が複数のファイル名で存在しても、URL は別です。バイトが同一であるだけでは安全に削除できません。作業元の `.afdesign` や `.HEIC`、古い CSS も、用途が確認できるまで保留します。

整理する際は、変更前の一覧を保存し、対象と参照を書き出してから、生成元と参照を更新して検証します。新しい画像はブラウザ向けの実際の画像形式と分かりやすい名前で追加します。Drive の共有ページやログイン HTML を画像として保存しないでください。監査はそのような形式の不一致も検出します。

### 取得元の変更とファイル名の衝突

通常の自動取得対象は、GAS が扱う画像の列と、対応するテキスト項目の Dropbox Markdown リンクの画像です。PDF は下記の扱いでリンクを維持します。通常のリンクや任意の HTML / CSS 内の外部 URL を、一律に画像として取得しません。

通常のページ更新でも、選択ページが使う外部・Drive 画像の変更を確認します。Drive はファイルの更新情報、外部 URL は条件付き GET の ETag / Last-Modified を使い、必要な場合に画像の実体を取得します。HTTP の確認情報がない場合は実体を取得します。HTML 行が再利用できる場合も、その前にこの確認を行います。Rebuild と外部論文データの再取得でも画像の変更確認を行い、元のファイル名を変えずに画像を差し替えた場合も更新対象です。明示的に取り直す場合は `Refresh linked assets on current page` を使い、画像は条件付き GET や更新時刻による省略をせず実体を取得します。リポジトリ内の相対パスを直接指定した資産は外部から取得し直しません。

### PDF と初回同期の所要時間

通常の更新・Rebuild・外部論文データの再取得では、PDF の内容を取得・自動同期しません。取得元との対応と公開 SHA を確認できる保存済みのファイル、既存の `pdf/元のファイル名`、元の外部 URL の順でリンクを維持します。既存の公開 PDF を削除・移動せず、画像と本文の更新を進めます。

PDF も取得し直したい場合は、`Refresh linked assets on current page` を明示的に使います。Drive / Dropbox PDF が16 MiB以下なら同期を試みます。取得前に Drive の `getSize`、または HTTP GET の `Range: bytes=0-0` と `Content-Range` からサイズを確認します。サイズ上限を超える場合や HTTP のサイズ確認を行えない場合は既存ローカル版または外部リンクを維持します。Range を無視した HTTP 200 の実体は二重ダウンロードせず再利用し、実体の取得後に上限超過と分かった場合もリンク維持とします。

出版社など、Drive / Dropbox 以外の外部 HTTP PDF は、`Refresh linked assets on current page` でも同期しません。既存の公開ファイルがあればそのリンクを維持し、なければ元の外部 URL を維持します。

通常の更新で維持した PDF も含め、PDF リンクを維持した件数は `pdfLinksPreserved` として、元の URL を出さずに実行結果へ通知します。この通知は PDF の内容を最新に同期できたという意味ではありません。必要な場合は元のリンクを確認し、明示的な再取得または手作業で公開版を更新してください。

PDF も自動同期する試行では、Publications の初回更新が360.913秒で Apps Script の約6分の実行上限に到達しました。PDF の取得・サイズ確認が積み重なるため、通常の自動同期を画像に限定しています。画像も初回には取得が必要なので、通常の変更確認と全資産の強制再取得を使い分けます。この変更後のネイティブでの成功・速度確認は [検証記録](verification.md) に別途記録します。

画像の変更確認は HTML の再利用時にも行うため、通常の更新でも通信が発生します。画像のみ同期する Publications のネイティブ検証では、初回は121.7秒で132行を生成し、8画像を保存しました。次の更新は22.275秒で132行を再利用し、GitHub への書き込みは0件でしたが、8取得元のうち5件は未変更確認、3件は画像を取得し直して同一内容と確認しました。確認情報を使えない取得元では実体の取得が必要になるため、転送が全くないことや、以前より常に短時間で終わることは保証しません。

外部・Drive 資産の生成名は `元の名前--取得元のハッシュ12桁.拡張子` です。別の取得元が同じファイル名を使っていても、同じ公開先を奪い合わないようにします。同じ取得元の画像を更新するときは、その対応先を維持します。初回は、現在の取得元の実体を検証して新しい名前で保存し、参照を切り替えます。旧来の公開ファイルや過去の生成物も残し、参照の切り替えと同時に削除しません。

CMSの更新とは別に、参照を監査して承認されたプレビュー資産の整理を行いました。未参照候補の保管・復元と、原本を維持した配信用画像の生成は [資産整理](assets/maintenance.md) を参照してください。通常のCMS更新は未参照候補を自動削除しません。

既存の大きな画像については32MiBまで実体・形式・SHAを検証し、同じ内容のGit blobが確認できた場合だけ再利用します。新規または変更された16MiB超の画像はCMSからアップロードせず、GitHubで追加するようエラーを通知します。32MiB超は検証対象外です。HTTPで取得済みの応答サイズを確認する場合もあるため、この上限はネットワーク転送そのものの厳密な上限ではありません。

Drive の識別子はファイル ID、HTTP の識別子は scheme / host を小文字にした URL のパスとクエリです。fragment は除外し、Dropbox の `dl` / `raw` だけを識別に使いません。その他のクエリ値と順序は保持します。署名 URL の再発行などでこの識別子が変わる場合は別の取得元として扱うため、新しい公開ファイルが作られることがあります。

専用 Sheet の `_cms_assets` は表示されたままの自動管理タブです。次の10列を GAS が管理します。本文・画像指定の編集元は各コンテンツタブであり、取得元の対応表を手作業で変更しません。元の URL や共有情報を含むため、このタブの書き出しを公開リポジトリや資産一覧へ保存しません。

| 列 | 内容 |
| --- | --- |
| `SourceKey` | 取得元を対応させる内部キー。 |
| `Identity` | Drive ID または正規化した HTTP URL。 |
| `SourceURL` | 実際の取得元 URL。 |
| `Path` | 公開するローカルパス。 |
| `BlobSHA` | 公開する内容の Git blob SHA。 |
| `ETag` | HTTP の条件付き取得に使う値。 |
| `LastModified` | HTTP の更新確認情報。 |
| `SourceModifiedAt` | Drive ファイルの更新時刻。 |
| `CheckedAt` | 最後に保存した取得元の確認時刻。現在の実行を省略する TTL ではありません。 |
| `RecordHash` | 対応記録の整合性を確認する値。 |

上記の PDF 同期省略・サイズ確認不能を除き、同期対象の HTTP / Drive 資産の取得や実体の検証が失敗した場合は公開を停止し、古い画像を成功した取得結果として黙って使いません。明示的な PDF 取得でも、HTML の偽 PDF や形式不一致を有効な PDF として保存しません。対応表は公開成功後、公開先の SHA と一致する記録だけをまとめて保存します。毎回画像の取得元を確認しても、SHA / ETag / Last-Modified / Drive 更新時刻が変わらない場合は `CheckedAt` を延長せず、対応表の書き直しも省略します。対応表の保存失敗は公開結果と分けて扱い、次回に公開先 SHA が一致しなければ条件を付けず取得し直します。

### 同じ公開 URL の表示を更新する

公開する `asset-versions.json` は、配信資産のローカルパスを、その内容の Git blob SHA（40桁）へ対応させる JSON です。取得元の URL や秘密情報は含みません。HTML・更新した画像と同じコミットへ保存し、`js/assets.js` が各画像・PDFリンク・ローカル CSS 内の資産 URL の `?v=` に SHA の先頭12桁を反映します。ヘッダーやホームページなど、本文の再生成対象でない場所でも、新しい版を取得できるようにします。クエリを除いた既存ファイルの公開パスは維持します。この JSON は全資産の検索用の対応表であり、載っていることを実際の使用の証拠として数えません。

ローカルで画像を追加・上書きした場合は、公開するバージョン情報と HTML の URL を次のコマンドで確認します。引数なしでは変更予定を表示するだけです。`--write` は `codex/preview` 上のローカル HTML と `asset-versions.json` を更新し、画像自体や Sheet の本文を変更しません。コミット・公開は別の操作です。

```sh
node scripts/version_assets.cjs
node scripts/version_assets.cjs --write
python3 scripts/site_audit.py --check
```

資産の全件一覧も更新する場合は、最新の private Sheet 書き出しを使って `site_audit.py` の `--output` / `--markdown` / `--catalogue` を指定します。実際のコマンドは [資産監査](assets/README.md#再生成) を参照してください。

取り込む画像・PDF は実体と拡張子が一致すること、HTML や空のファイルでないこと、1ファイルが16 MiB以下であることを確認します。画像の上限超過は明示エラー、PDF の上限超過は上記のリンク維持と通知です。同じ更新内で、同じ公開パスに異なる内容を保存しようとした場合は中止します。16 MiBを超える資産を公開先へ追加する場合は GitHub を使い、Sheet ではその公開パスを参照してください。

## 本番へ移すとき

この検証環境のリポジトリ名、ブランチ名、URL、`noindex`、Analytics、認証情報、隔離ガードは検証用です。検証結果をそのまま本番へコピーする操作は別の変更として扱い、差分と公開設定を確認します。検証作業中に本番側の機密情報・認証・Pages 設定を変更しません。
