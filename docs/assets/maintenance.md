## 表示用画像は配信物で生成

元画像の公開パスとバイト列を残したまま、ビルド時に `dist/site/img/optimized/` へ表示用 WebP を生成します。ソースの `img/` に派生画像は書き込みません。

- Member / Alumni の `.personal_photo` だけで使われる写真は、縦横比・ICC カラープロファイルを維持し、EXIF の向きを適用して長辺最大 1,024 px の画像にします。拡大はしません。CSS の写真枠の最大値は 230.4 px です。
- その他の PNG は全解像度を維持します。復号した画素と ICC が元画像に一致した場合だけ採用します。
- 個人写真以外の JPEG は元画像を使用します。科学図・ロゴ・大きな紹介写真を一律に縮小しません。画素一致に失敗した画像や容量が減らない画像も元画像を使用します。

今回採用した派生画像は 16 件（個人写真 11 件、全解像度 PNG 5 件）です。対応する元画像の合計 58,369,563 bytes が表示用画像の合計 10,868,102 bytes となり、81.4% 減りました。これは採用した画像ファイルの容量比較で、ページ全体の転送量や表示時間の測定ではありません。

| 元画像 | 元の bytes | 表示用 bytes | 表示用の幅 × 高さ |
| --- | ---: | ---: | ---: |
| `img/pfp.png` | 20,721,618 | 874,214 | 683 × 1,024 |
| `img/sanchit_profilePic.png` | 13,380,083 | 747,064 | 757 × 1,024 |
| `img/kazuki.jpg` | 3,517,848 | 824,642 | 768 × 1,024 |

採用・不採用理由、元画像と派生画像の SHA、画素検証結果は [optimization-manifest.json](optimization-manifest.json) にあります。縮小画像は同じ変換で生成した基準画像との全画素一致を確認しています。元の高解像度画像との全画素一致を意味しません。

配信物の `asset-versions.json` は、元 SHA と派生 SHA の両方が合う場合だけ `displayAssets` を採用します。HTML の画像、CSS の画像、実行時の動的画像を派生先へ切り替え、`a` / `area` のダウンロードリンクは元の高解像度画像を指し続けます。Sheet の画像 URL、CMS の画像保存先、`_cms_assets` / `_cms_cache` の仕様はこの表示用変換では変更しません。派生URLには `asset=元画像の公開パス` も付け、古いHTMLやCSSが残っていても最新の検証済み画像へ追従します。ローカルの JS、CSS、CSS の `@import` に共通の内容ハッシュを付け、古い JS と新しい表示画像の組み合わせを避けます。

## 検証と配信物の生成

```sh
npm ci --ignore-scripts
node scripts/asset_maintenance.cjs --check
node scripts/build_site.cjs --output dist/site
node scripts/build_site.cjs --verify --output dist/site
```

ビルド先は空の `dist/site` に限ります。再生成するときは生成済みの `dist/site` を片付けてから実行します。元画像のディレクトリを消す必要はありません。読み取り専用の `--verify` は派生 SHA、元 SHA、ローカル参照、配信対象の範囲を検証します。

配信物に含むのは、ルート HTML、`css/`、`js/`、`img/`、`img_new/`、`pdf/`、`site-settings.json`、`asset-versions.json`、`.nojekyll` です。`cms/`、`docs/`、`tests/`、`scripts/`、`private/`、`node_modules/` は含みません。元画像 216 件も元の公開パスで残ります。今回の配信物は派生画像を含めて 297 ファイル、397,325,710 bytes でした。

## 退避したファイルを戻す

```sh
# 元のパスを指定して 1 件復元
node scripts/asset_maintenance.cjs --restore --path img/top-image.jpg

# 退避した全件を復元
node scripts/asset_maintenance.cjs --restore
node scripts/asset_maintenance.cjs --check
```

復元は `codex/preview` に限定されます。非公開の保存物を優先し、ない場合は記録した Git blob を履歴から読みます。Git 履歴から復元する場合は、その blob を含む履歴の取得が必要です。CI の通常検証・ビルドは履歴を必要としません。既存パスに異なる内容がある場合は上書きせず停止し、成功した復元は公開の復元記録へ反映します。退避物そのものは Git へ追加せず、配信しません。

追加の退避は既存の公開・非公開マニフェストがある場合に停止します。今回の復元記録を上書きして次の整理を始めることはできません。新しい Sheet 書き出し、公開ページ、動的参照、必要な外部リンクを確認し、既存の復元記録を保持する次の整理方法をレビューしてから行います。

この記録は Preview の整理に限ります。本番への自動適用や、候補一覧を根拠にした本番ファイルの削除は行いません。
